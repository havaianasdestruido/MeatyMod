# Phase 2 — Implementation (MANDATORY)

Begin this phase **only after Phases 0 and 1 have been successfully completed**.

Do **not** begin implementation until every required report from the previous phases exists, has been reviewed, and is internally consistent.

The objective of this phase is to implement the modding tool exactly as specified by the research and planning documents. No functionality should be invented during implementation. If an implementation requirement cannot be fulfilled because of missing evidence or incomplete planning, stop and report the issue rather than making assumptions.

---

# Implementation Rules

The implementation must follow:

- All findings from Phase 0.
- All architectural decisions from Phase 1.
- All documented limitations.
- All validation requirements.
- All security requirements.
- All testing requirements.

Implementation must never contradict previous reports.

---

# Development Methodology

Develop the application incrementally.

Only one milestone should be actively implemented at a time.

For every milestone:

1. Review affected documentation.
2. Identify dependencies.
3. Implement.
4. Verify compilation.
5. Run automated tests.
6. Perform manual validation.
7. Update documentation.
8. Commit milestone.

Do not begin the next milestone until the current one is stable.

---

# Coding Standards

The codebase must:

- follow a consistent coding style
- use descriptive naming
- minimize duplication
- maximize maintainability
- separate concerns
- use dependency injection where appropriate
- avoid unnecessary global state
- avoid hardcoded values
- avoid magic numbers
- prefer immutable data where practical
- include meaningful comments where implementation is non-obvious

# Completion Criteria

Phase 2 is complete only when:

- Every planned module has been implemented.
- The application builds successfully without errors.
- All planned features have been implemented or explicitly deferred.
- Automated tests pass.
- Validation passes.
- Documentation is up to date.
- Progress reports are complete.
- No known critical defects remain.

Only after these conditions are met may the project proceed to Phase 3 (Quality Assurance, Optimization, and Release Preparation).
