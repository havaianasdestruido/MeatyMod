# Mod package (`mod.zip`)

A mod package is an ordinary zip archive produced by [`meatymod pack`](../cli/pack.md), with one convention on top: a `checksums.txt` at the archive root listing the SHA-256 of every other entry.

## Layout

```text
mod.zip
├─ checksums.txt        ← generated by pack
├─ manifest.json
├─ config.txt
├─ README.md
├─ build.bat
├─ run.bat
├─ lib/
│  └─ xna/*.dll
└─ src/
   └─ Oink/*.cs
```

| Property | Value |
| --- | --- |
| Container | zip (`System.IO.Compression.ZipArchive`) |
| Compression | `CompressionLevel.Optimal` (Deflate) |
| Entry paths | relative to the mod directory, **forward slashes** |
| Excluded | any path segment named `bin` or `obj` (case-insensitive), any segment starting with `.` |
| Size limit | files over 100 MiB are skipped with a warning |

## `checksums.txt`

One line per packed file:

```text
<relative/path><2 spaces><64 lower-case hex SHA-256>
```

```text
build.bat  3c0a…71
config.txt  9ab0…4e
manifest.json  5f1d…9a
src/Oink/OinkEntry.cs  1c55…7f
```

Written as UTF-8 **without** a BOM. It does not contain an entry for itself. The same lines can be regenerated for a working tree with [`meatymod checksum <dir>`](../cli/checksum.md) (minus the trailing `Files: n` line, and without `pack`'s exclusions).

### How `install` uses it

1. Parse every line — split on the **first double space**; a line without one is reported as `checksums.txt: malformed line: "…"`.
2. For each listed path, find the zip entry — missing ⇒ `checksum mismatch: <path> is listed in checksums.txt but is missing from the archive`.
3. Hash the entry stream and compare case-insensitively — mismatch ⇒ `checksum mismatch: <path> (expected …, got …)`.
4. Any error at all aborts the install **before** a single file is written.

:::caution Verification only covers what the file lists
`VerifyChecksums` iterates the **entries named in `checksums.txt`**, never the entries in the archive. Two consequences:

- an archive with **no** `checksums.txt` installs with no verification whatsoever — `VerifyChecksums` returns an empty error list and the install proceeds;
- an archive whose `checksums.txt` omits some files installs those files **unverified**. Nothing cross-checks that every zip entry is listed.

`pack` always writes a complete list, so this only bites on hand-made or edited archives.
:::

:::caution Integrity, not authenticity
The list lives inside the archive it describes. It catches truncation, corruption and accidental edits; it does not catch an attacker who repacks the zip and recomputes the hashes. There is no signing, and MeatyMod will not add one. See the [security model](../architecture/security-model.md).
:::

## Content mods vs code mods

`pack` skips any path whose segments include `bin` or `obj` (case-insensitive) or begin with a dot. It has no rule about file **extensions**, so what gets excluded depends on where a file sits, not on what it is:

- a DLL built to `src\MyMod\bin\Release\net40\MyMod.dll` is **excluded**, because of the `bin` segment — which is where every mod in this repository builds to, so in practice the compiled mod is not in the archive;
- a DLL sitting anywhere else — `MyMod\Mod.dll`, say — is **included** like any other file. The `PackAndInstall_RoundsTripToGameContent` test relies on exactly that: it writes `Mod.dll` at the mod root and asserts it arrives at `Content\Mod.dll`.

Keeping build output out of the archive is deliberate — the two distribution paths are separate:

| Mod kind | Ships | Installed with |
| --- | --- | --- |
| Content mod (assets, TXT tuning) | files that belong under `Content\` | [`install`](../cli/install.md) |
| Code mod (a .NET DLL) | the built DLL | [`inject`](../cli/inject.md) |

A mod can be both. The shipped examples (`Oink`, `QuackMenu`) are code mods whose archives carry source, config and docs — useful for distribution and review, but the thing you actually inject is the DLL you build.

## Installing

```bat
meatymod install mod.zip "game\Blood and Bacon"
```

Entries are extracted under `<game>\Content\`, after a [containment check](../architecture/security-model.md#path-containment-on-install-zip-slip) and a size check. Overwritten files are mirrored into `<game>\Backups\MeatyMod\` first.

## Building a package by hand

`pack` is just a convention; you can produce an equivalent archive yourself as long as:

- entry paths use forward slashes and are relative to the mod root;
- `checksums.txt` is at the archive root in the format above (or absent entirely);
- no entry path escapes the content root when combined with it;
- no entry exceeds 100 MiB.
